QGIS Launcher (qgis_launcher) v2.4.0

QGIS / QField 起動ランチャー — Web UI・HTTP API・CLI で動作する Rust(Axum) 製デスクトップランチャーのドキュメント

2. 🔄 起動処理の流れ（内部動作）

qgis_launcher.exe が実行されてから QGIS が起動するまでの内部処理を、実装（src/main.rs）に沿って図解します。

kasugai-qgis: プロトコル経由の起動: サーバー停止後に残ったブラウザタブが kasugai-qgis://open へ遷移すると、EXE が URI 位置引数付きで再起動しヘッドレスサーバとして立ち上がります。タブ側は /health をポーリングして復帰を検出します。

図3: QGIS 起動処理（launch_qgis — CLI モードと POST /launch 共通）

flowchart TD
    A(["launch_qgis(profile, project_paths, exe, role, dev_mode)"]) --> B["QGIS 実行ファイルの決定（優先順位）
1. CLI --qgis-executable（明示指定）
2. settings.qgis_executable（実在確認あり）
3. CLI 時: プロジェクトの version 属性に合致する
   インストール済み QGIS を自動選択
  （major.minor 一致 → major 一致 → 文字列包含の順）
4. レジストリの .qgs 関連付けから検出"]
    B --> C{"実行ファイルが見つかった?"}
    C -- "いいえ" --> C1["エラーを出力して起動中止"]
    C -- "はい" --> D["ロール制御ファイル準備
・--customizationfile ini/ROLE.xml
  （QGIS4 用・ファイル存在時のみ）
・ini/qgis_global_settings.ini を生成
   [Variables] userrole=ROLE
・--code ini/startup.py（ファイル存在時のみ）"]
    D --> E["子プロセスへ環境変数を注入
PORTAL_USERROLE=ROLE"]
    E --> F{"dev_mode?
--dev or settings.dev_mode"}
    F -- "はい" --> F1["QGIS Live Harness 用環境変数を注入
QTWEBENGINE_REMOTE_DEBUGGING=9222
QTWEBENGINE_CHROMIUM_FLAGS（--disable-gpu 等）
WEBENGINE_AUTOOPEN=1
WEBENGINE_LIVE_DIR / WEBENGINE_LOG_PATH
WEBENGINE_DEV_SRC（junction 配置時のみ）"]
    F -- "いいえ" --> G["project_path 各エントリを解決
・.qgs/.qgz → そのファイル
・フォルダ → 直下の .qgs/.qgz の先頭
・解決不可 → プロジェクト無しで起動"]
    F1 --> G
    G --> H["qgis.exe / qgis.bat を spawn
--profile PROFILE
+ --customizationfile / --globalsettingsfile / --code
+ プロジェクトパス（位置引数）
.bat/.cmd は cmd.exe /C 経由"]
    H --> I{"呼出し経路"}
    I -- "POST /launch" --> I1["応答返却後 500ms で
ランチャーサーバを自動停止"]
    I -- "--cli" --> I2["ランチャー終了"]

図4: 自動更新フロー（GET /update ・ POST /update/apply）

flowchart TD
    A(["GET /update（UI からの更新確認）"]) --> B{"update_check_enabled?
--no-update-check 無し かつ
update_check ≠ false かつ update_url 有効"}
    B -- "無効" --> B1["available:false + disabled:true を返す"]
    B -- "有効" --> C["check_nsis_update
update.json を GET
（既定: GitHub Pages 上の update.json）"]
    C --> D{"remote version > 現在の version?"}
    D -- "いいえ" --> D1["最新版 → available:false"]
    D -- "はい" --> E["available:true + version/url/full_url
/full/notes を返す
（ループガードの blocked 情報も付与）"]
    E --> F["ユーザー操作で POST /update/apply"]
    F --> G["prepare_nsis_update
・ループガード確認（update_state.json。
  同一バージョンへの試行は1回/24hまで）
・full ? full_url : url のインストーラを
  %TEMP%\kasugai_qgis_setup.exe へダウンロード
・sha256 があれば SHA-256 検証
・試行を記録（record_update_attempt）"]
    G --> H["run_nsis_installer_and_exit
installer /S /D=INSTALL_DIR を起動し
本体プロセスは終了"]
    H --> I["NSIS が qgis_launcher.exe を上書きし
新しい exe を自動起動"]
    I --> J["次回起動時に reconcile_update_state で
到達を確認 → 記録クリア"]

起動時に更新を自動適用しないのは意図的です（適用直後の再起動で再び更新が走り、無限ループになるため）。起動時は試行結果の照合のみを行い、適用は POST /update/apply のユーザー操作起点のみです。

図5: プロファイル強制更新フロー（Reset Profiles — POST /reset）

Web UI の「Reset Profiles」ボタンから実行される強制更新処理です。詳細は「プロファイルの強制更新（Reset Profiles）」も参照してください。

flowchart TD
