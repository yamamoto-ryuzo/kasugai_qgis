QGIS Launcher (qgis_launcher) v2.4.1

QGIS / QField 起動ランチャー — Web UI・HTTP API で動作する Rust(Axum) 製デスクトップランチャーのドキュメント

2. 🔄 起動処理の流れ（内部動作）

qgis_launcher.exe が実行されてから QGIS が起動するまでの内部処理を、実装（src/main.rs）に沿って図解します。

図1: 全体シーケンス（起動～初期化）

flowchart TD
    A(["qgis_launcher.exe 起動"]) --> B["CLI 引数をパース
--port / --no-update-check

    B --> D["カレントディレクトリを EXE 所在フォルダへ変更"]
    D --> E["設定読込（3段マージ・後勝ち）
① qgis_settings.json（ベース）
② qgis_settings_override.json（全ユーザー強制）
③ qgis_settings_USERNAME.json（最終適用）"]

flowchart TD
    S(["起動処理入り口"]) --> P2["待受ポート決定

・subst drive=local_cache でドライブ割当"]
    P3 --> P3B["mode=sync: sync_drive

  をバックグラウンドで spawn
・read_only → --read-only
  vfs_cache_* / vfs_write_back をオプション透過

URI 起動"}
    Q -- "はい（開発用）" --> R1["run_api_server_sync
axum サーバを同一スレッドで起動"]
    Q -- "いいえ" --> R2["run_gui_server

URI 位置引数付きの起動（開発用）: 外部プロセスが qgis_launcher.exe <URI> を spawn すると、ウィンドウを開かずヘッドレスサーバとして立ち上がります。 URI の内容は参照されません。現在の利用者は run.py の開発フローのみで、ブラウザから http://127.0.0.1:8500/ にアクセスして Playwright 検証を行います。KASUGAI 等が埋め込みペインで利用する場合の経路としても残しています。

    B --> C{"実行ファイルが見つかった?"}

  （QGIS4 用・ファイル存在時のみ）

   [Variables] userrole=ROLE

    D --> E["子プロセスへ環境変数を注入

    G --> H["qgis.exe / qgis.bat を spawn

    H --> I1["応答返却後 500ms で

図4: 自動更新フロー（GET /update ・ POST /update/apply）

flowchart TD
    A(["GET /update（UI からの更新確認）"]) --> B{"update_check_enabled?
--no-update-check 無し かつ
update_check ≠ false かつ update_url 有効"}
    B -- "無効" --> B1["available:false + disabled:true を返す"]
    B -- "有効" --> C["check_nsis_update
update.json を GET
（既定: GitHub Pages 上の update.json）"]
    C --> D{"remote version > 現在の version?"}
    D -- "いいえ" --> D1["最新版 → available:false"]
    D -- "はい" --> E["available:true + version/url/full_url
/full/notes を返す
（ループガードの blocked 情報も付与）"]
    E --> F["ユーザー操作で POST /update/apply"]
    F --> G["prepare_nsis_update
・ループガード確認（update_state.json。
  同一バージョンへの試行は1回/24hまで）
・full ? full_url : url のインストーラを
  %TEMP%\kasugai_qgis_setup.exe へダウンロード
・sha256 があれば SHA-256 検証
・試行を記録（record_update_attempt）"]
    G --> H["run_nsis_installer_and_exit
installer /S /D=INSTALL_DIR を起動し
本体プロセスは終了"]
    H --> I["NSIS が qgis_launcher.exe を上書きし
新しい exe を自動起動"]
    I --> J["次回起動時に reconcile_update_state で
到達を確認 → 記録クリア"]

起動時に更新を自動適用しないのは意図的です（適用直後の再起動で再び更新が走り、無限ループになるため）。起動時は試行結果の照合のみを行い、適用は POST /update/apply のユーザー操作起点のみです。

図5: プロファイル強制更新フロー（Reset Profiles — POST /reset）

Web UI の「Reset Profiles」ボタンから実行される強制更新処理です。詳細は「プロファイルの強制更新（Reset Profiles）」も参照してください。

flowchart TD
    A(["Web UI「Reset Profiles」ボタン押下"]) --> B["POST /reset
reset_profiles_handler"]
    B --> C["進捗キューをクリアし
spawn_blocking で reset_profiles を実行
PROG: / MSG: を /progress へ送信"]
    C -.-> P["UI は GET /progress をポーリング
モーダルで進捗表示"]
    C --> E{"settings_dir\profiles\ 存在?"}
    E -- "なし" --> E1["distribution profiles not found
で失敗を返す"]
    E -- "あり" --> F["① 既存プロファイルの削除
%APPDATA%\QGIS\QGIS{major}\profiles\ 配下を全削除
（profiles\ 無しの構成では
QGIS{major}\ 直下のディレクトリを削除）"]
    F --> G["② copy_profiles_at_startup を再実行
起動フォルダの profiles\ 直下を
%APPDATA%\QGIS\ へ再コピー
（削除済みのため全ファイル新規配置 = 強制更新）"]
    G --> H["MSG:done → { ok: true } を返却
モーダル自動クローズ"]
