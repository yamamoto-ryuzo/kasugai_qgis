1. Web タブ — サーバレス Web 配信

geo_webview ドキュメント / 使い方

使い方

Web タブは2つのグループで構成されます。「Web配信（サーバレス）」が主機能（QGIS プロジェクト → .kasc+canvas_data/ 出力とブラウザ起動）、 「HTTP Server」が補助（出力物の配信・起動経路の土台）です。

エクスポート・出力設定

  • Export — 出力先へ .kasc+canvas_data/+<engine>.html+index.html を書き出す（起動・登録・ZIP 生成はしない）
  • ZIP — エクスポート一式を kasugai_canvas_<チャンネル>.zip としてブラウザダウンロード（要 HTTP サーバー稼働）
  • 出力先 — フォルダ名ボタン（クリックで選択、↺ で既定リセット、📁 で開く）
  • Format: — ベクター出力形式 native/recommended/geojson
  • Visible data only — チェック時は現在の表示範囲の地物のみ出力

起動（CDN・Engine）

  • CDN: — 起動するエンジンの供給元。 stable/unstable=ホスト版 CDN（アプリ不要・要インターネット）、canvas=稼働中の Canvas アプリ（:8510）、custom=カスタム（URL/FILE）欄の値（http(s) URL=自前ホスト、フォルダパス=ローカル web/ を本サーバが配信）
  • Engine: — ▶ WebView が開くエンジン（Cesium/MapLibre/OpenLayers/Leaflet/GSI Maps/Navara）
  • ▶ WebView — エクスポート → route 変換・起動先解決 → ブラウザ起動まで一発実行。開かれる .kasc は必ず最新

KASUGAI Canvas アプリ連携

  • Install KASUGAI Canvas — アプリのインストール専用（セットアップ=NSIS・.kasc 関連付けあり / ポータブルZIP）
  • Canvas Customize — 稼働中アプリの /admin/ UI設定画面を開く

HTTP Server

  • ステータス表示・Enable トグル・ポート番号（既定 8089）・:80/:443 プリセット
  • Check — 到達性診断・ファイアウォールルール追加

設定・ツール仕様

Web タブは2つのグループで構成されます:

  • Web Distribution (Serverless) グループ （groupBox_webdist）— ? ヘルプ、Export（ファイル出力のみ）、 ZIP（エクスポート一式のダウンロード）、出力先フォルダ選択/リセット/開く、 Format: コンボ（native/recommended/geojson）、Visible data only チェック、CDN: コンボ（stable/unstable/canvas/custom）＋カスタム（URL/FILE）欄＋… 参照、 Engine: コンボ（4エンジン＋vendored 2系統）、▶ WebView（エクスポート→ブラウザ起動）、 Install KASUGAI Canvas、Canvas Customize（アプリの /admin/ UI設定画面）。
  • HTTP Server グループ（groupBox_server）— サーバーステータス表示、Enable トグル、ポート番号（既定 8089）、 :80/:443 プリセット、Check（到達性診断・ ファイアウォールルール追加）。

起動経路

経路 呼び出し 用途
パネルボタン ▶ WebView ボタン (plugin.py: on_kasugai_launch_clicked('hosted')) 人手操作。エクスポート→route 変換→ブラウザ起動まで一発で行う（図1）。パネルの Engine: コンボで起動エンジンを選択（QSettings kasugai_engine に保存）。CDN: コンボのエンジン供給元モードに従う:stable/unstable=kasugai-canvas-web のホスト版エンジン（アプリ未導入で完結）、canvas=稼働中 Canvas アプリ :8510（ネイティブ一体運用・route=kasugai）、custom=「カスタム（URL/FILE）」欄の値で判定（http(s) URL=自前ホスト / フォルダパス=FILE モードで本サーバがその web/ を配信）。モードは QSettings kasugai_hosted_channel、実値は kasugai_hosted_value に保存（設定ダイアログと共通）。Install KASUGAI Canvas ボタンは常時インストール専用（セットアップ=NSIS・.kasc 関連付けあり / ポータブルZIP=展開のみ）、Canvas Customize ボタンは稼働中アプリの /admin/ UI設定画面を開く
パネルボタン Export ボタン (plugin.py: on_kasugai_export_clicked) 人手操作（ファイル出力のみ。Canvas 起動・登録はしない。ZIP は生成しない）
パネルボタン ZIP ボタン (plugin.py: on_kasugai_zip_clicked) エクスポート物一式を kasugai_canvas_<チャンネル>.zip としてブラウザダウンロード。/export-data/ がオンデマンドで ZIP を生成して返す（要 HTTP サーバー稼働）。CDN コンボのチャンネルがファイル名に反映される
HTTP GET http://localhost:8089/kasugai (server_manager._handle_kasugai) 外部アプリ・AI からの一発起動。?engine= で起動エンジン指定可。応答は {ok,url,via,dir,layers,tiles,engine} JSON
Bridge bridge_call の kasugaiExport(output_dir, open_app, native_formats, hidden_as_off, emit_themes, emit_bookmarks, emit_launchers, engine, install, route, use_existing, emit_atlas, link_files, vector_format, visible_data_only, progress_cb, site_control) Live Driver 経由の AI 制御（MCP qgis_bridge_call / REST /api/cmd / JSONL）。use_existing=True で再エクスポートせず既存の .kasc のみ使用（未出力なら code=not_exported）

形式選択（vector_format）は全ルート共通の単一経路で .kasc+canvas_data/ の中身を決め、CDN モード（エンジン供給元）とは独立 — どのモードでも同じ形式が効く。route 変換だけがモード依存。

出力フォルダ構成

<out_dir>/                    # 既定: <ドキュメント>/kasugai_canvas_qgis
├─ kasugai_canvas.kasc        # インスペクタ設定(外部プロジェクト登録対象)
├─ project.json               # {"title": ...}
├─ index.html + <engine>.html # 起動ランチャ(emit_launchers 時)
├─ bookmarks.xml              # qgis_bookmarks 形式(emit_bookmarks 時)
├─ live.json                  # live 連携マニフェスト(live_sync 時)
└─ canvas_data/
   ├─ *.geojson               # geojson モード変換 / 変換失敗時の最終フォールバック(EPSG:4326)
   ├─ *.fgb                   # recommended 変換 / ネイティブ参照の FGB(複製)
   ├─ *.gpkg                  # ネイティブ参照の GPKG(複製)
   ├─ *.parquet               # ネイティブ参照の Parquet(複製) / FGB ドライバ無し時の変換先
   ├─ *.shp + sidecars        # ネイティブ参照(.dbf/.shx/.prj 等を一式複製)
   ├─ *.csv / *.tsv           # duckdb: 参照の区切りテキスト(複製)
   ├─ *.gpx/.kml/.topojson 等 # その他ネイティブ参照の複製(_NATIVE_KINDS)
   ├─ *.tif / *.tiff          # geotiff: 行のローカル GeoTIFF/COG(複製)
   ├─ *.png                   # image: 行のラスタ焼き付け PNG(非 GeoTIFF・再現不能レンダラ)
   ├─ <dir>/                  # ローカル 3D Tiles / ローカル XYZ タイルの複製(1GiB 上限)
   ├─ <slug>_xyz/            # 大規模・複雑スタイルのベクター焼き付け XYZ({z}/{x}/{y}.png + index.html、§5)
   ├─ anim3d_*.geojson        # 3D ビューアニメーションのカメラ軌道(fly_geojson: 行)
   ├─ atlas_*.geojson         # アトラス巡回パス(fly_geojson: 行)
   ├─ *.qml                   # 各ベクターの QGIS スタイル(<slug>__<theme>.qml = テーマ別名付きスタイル)
   ├─ *.svg / *.png 等        # .qml が参照するシンボル画像(QGIS 内蔵SVG・ローカル画像の複製)
   └─ custom-layer.js         # site= 出力時の custom-layer プラグイン JS(§3)

起動 HTML（index.html・<engine>.html）は ?kasc=<.kasc URL> 付きで対応エンジンへ転送し、エンジン本体を ./ ../ ../../ / の順に自動探索（CANVAS_BASE で差し替え可。 エンジン未検出時は HOSTED_BASE のホスト版エンジンへ誘導）。

その他: attr= に QGIS レイヤの出典(attribution)を引き継ぐ。 where= は行の最終オプションで、値は改行までが式 (|| 連結・'a|b' リテラル等の | を含んでよい)。 where-eval.js は || 連結に対応済み(単独 |・% は非対応)。 off や他の key=value は where= より前に置く。 view: の ;where= は行内トークンのため対象外(値に | は書けない)。 全レイヤ行で minScale=/maxScale= に QGIS の「縮尺による表示」 (minimumScale=引き側限界・maximumScale=寄り側限界)を出力する。 Canvas 側は同じ範囲で表示/非表示を切り替える。 .qml 書き出し後、シンボルレイヤが参照する画像(SvgMarker/RasterMarker/ SVGFill/RasterFill 等の name/imageFile/svgFile/file)を実ファイルへ 解決して canvas_data/ へ複製し、.qml 内の参照を canvas_data/ 内のファイル名へ書き換える (QGIS 内蔵SVGの transport/… 等の相対名は QgsApplication.svgPaths() で 解決。http(s)/data/base64: 参照はそのまま維持。解決不能は warnings 記録)。 sql: 行は QGIS 側に対応する任意クエリソースが無いため出力しない （クエリ系は duckdb: の宣言的オプションで網羅する）。

ベクター出力形式（native / recommended / geojson）

ベクターレイヤの出力方針を切り替える「推奨形式スイッチ」 （QSettings kasugai_vector_format、既定 native）。 切替は4経路あり、パネル/設定ダイアログは永続設定を読み書きし、 URL/bridge は当該エクスポートだけの一時上書き（いずれも相互に同期）:

  • パネルの Format: コンボ （native (reference as-is) / recommended (FlatGeobuf → canvas_data/) / geojson (WEB interop → GeoJSON)）— 永続
  • 設定ダイアログの Vector Export Format コンボ — 永続
  • GET /kasugai?fmt=recommended|native|geojson — そのリクエストのみ上書き （応答 JSON に vector_format を含む）
  • bridge kasugaiExport(vector_format='recommended'|'native'|'geojson') — 呼出しのみ上書き
モードベクターの扱い
native（既定） 読めるソースはそのまま参照（gpkg:/geojson:/shp:/wfs:/duckdb:/flatgeobuf:/geoparquet: 行）。非ネイティブ形式のみ変換（下表のフォールバック）
recommended FlatGeobuf/GeoParquet 以外の全ソースを FlatGeobuf（EPSG:4326・空間インデックス付き）へ変換し canvas_data/ へ flatgeobuf: 行で配置。既に FlatGeobuf/GeoParquet のソースは参照を維持（flatgeobuf:/geoparquet:/duckdb:+format=parquet 行）。subsetString・fields/where/limit は変換データへ焼き込み。Canvas 側では bbox=auto の範囲読みが効く（flatgeobuf: は空間インデックス+Range、geoparquet: は covering.bbox 列または行グループ geospatial statistics による部分読み。いずれも無いファイルは全件へフォールバック）
geojson（WEB連携） 全ベクター（FlatGeobuf/GeoParquet ソース含む・WFS/メモリ等も）を GeoJSON（EPSG:4326）へ変換し canvas_data/ へ geojson: 行で配置。canvas_data/ がオープン標準の GeoJSON のみになるため、KASUGAI Canvas 以外の WebGIS・GIS ツールでもそのまま読み込める相互運用向けモード

変換ドライバは FlatGeobuf が第1候補（非搭載環境は Parquet）で、 変換失敗時は GeoJSON(EPSG:4326) へフォールバックする（native モードの非ネイティブ変換と同じ経路）。 geojson モードは GeoJSON 固定（ドライバ切替なし）。

非表示レイヤの出力省略（表示中のみ変換）

非表示レイヤ（hidden_as_off=True またはマップテーマ存在時に | off で出力されるレイヤ）を .kasc のレイヤ行へ一切出力しない 高速化スイッチ（QSettings kasugai_visible_data_only、既定 ON）。 Canvas のレイヤ一覧に非表示レイヤが並ばず、データ変換・ canvas_data/ へのコピー・スタイル書き出しのコストも掛からない。 背景図グループ内の XYZ タイルなど base: 候補のみ従来通り | off 付きで出力する（ベースマップ選択の候補）。スキップされた レイヤは Canvas で表示に切り替えられない（skipped に理由付きで 記録）。theme: 行は実際に出力されたレイヤのみを対象とする。 OFF で従来通り非表示レイヤも | off 行として全データを変換・ 複製する（プロジェクトの丸ごと引越し用途）。

切替経路（パネル/設定ダイアログは永続設定を読み書き、 bridge/API 引数は当該エクスポートだけの一時上書き）:

  • パネルの Visible data only (faster) チェック — 永続
  • 設定ダイアログの Vector Export Format 内にある同名チェック — 永続
  • bridge kasugaiExport(visible_data_only=True|False) — 呼出しのみ上書き
  • export_kasugai_project(visible_data_only=…) — 呼出しのみ上書き

エクスポート進捗（progress_cb）

export_kasugai_project / bridge kasugaiExport に progress_cb(done, total, name) を渡すと、レイヤツリー走査の 各レイヤ処理開始時に「何件目/全何件・対象名」を通知する （全件完了時は (total, total, '')）。パネルのエクスポート/ 起動ボタンは QProgressDialog に「レイヤーを変換中 N/M: 名前」 とバーを表示し、Cancel 押下で ExportCancelled を送出して 中断できる（bridge は code: 'cancelled' で返す）。 GET /kasugai 経路は GUI を持たないため同形式の進捗を QgsMessageLog へ記録する。

.qml スタイル出力

スタイル（.qml）はベクターデータ形式とは独立で、 native/recommended/geojson のどのモードでも同じ扱い:

  • 出力される全ベクターレイヤについて layer.saveNamedStyle() で canvas_data/<slug>.qml を書き出し、.kasc 行へ | style=canvas_data/<slug>.qml を付与する。 ネイティブ参照行（gpkg:/flatgeobuf: 等）でも 変換行（flatgeobuf:/geojson:）でも付き方は同じ
  • .qml の中身は <renderer-v2>（シンボル）・ <labeling>/<text-style>（ラベル）・ 時間設定等の QGIS レンダラ定義。Canvas 側は qml-style.js+<engine>/qml-render.js が これをエンジン描画へコンパイルする（データ形式ではなくスタイル再現の責務）
  • ユーザー定義関数（geo_userfunc の @qgsfunction）を含む式属性は 書き出し時に宣言式へ展開する（配布物を組込み関数のみにする）
  • シンボル画像（SvgMarker/RasterMarker/SVGFill/RasterFill 等）の参照は canvas_data/ へ複製し .qml 内パスを書き換える（前述「その他」の通り）
  • 差分エクスポート（changed）では style 変更のあったレイヤのみ .qml を再書き出しし、未変更レイヤは既存 .qml を再利用する

スタイルの配布経路は .qml+style= の1系統に統一 （v4.21.0 で GPKG layer_styles への書き込み経路 embed_gpkg_style は廃止）。

KASUGAI 側への反映

起動中の KASUGAI ローカルサーバー（KASUGAI_CANVAS_PORT、既定 8510）が あれば POST /api/projects/register で外部プロジェクト登録し、 POST /api/command の switchProject で表示を切り替える。

Canvas が使えない場合は次の順でフォールバックする （/kasugai・kasugaiExport とも応答の via で供給元を返す）:

via 条件 URL
kasugai Canvas 稼働（or exe/関連付けで起動成功） http://127.0.0.1:8510/<engine>/?project=<id>
qgis-http Canvas 未起動だが インストール済み web/ あり http://localhost:<port>/<engine>/?kasc=<export-data URL>
hosted Canvas 未インストール（要インターネット） https://yamamoto-ryuzo.github.io/kasugai-canvas-web/<channel>/<engine>/?kasc=<export-data URL>
null いずれも不可 出力のみ成功
  • qgis-http: geo_webview の HTTP サーバーが エンドポイントに一致しなかった パスをインストール済み Canvas の web/ 配下へ静的解決する （find_kasugai_web_dir()）。同一オリジンのため混在コンテンツ問題なし
  • hosted: エンジン本体は kasugai-canvas-web（GitHub Pages）から取得し、 .kasc+canvas_data/ は本サーバーの /export-data/ から読む。https→localhost の fetch は Chrome Private Network Access 対象のため、サーバーは OPTIONS プリフライトに Access-Control-Allow-Private-Network: true で 応答する。モードは設定 kasugai_hosted_channel （stable/unstable/カスタムURL、既定 stable）で、 パネルの CDN: コンボ（stable/unstable/canvas/custom + 「カスタム（URL/FILE）」欄の実値 kasugai_hosted_value）または設定ダイアログから変更する
  • エンジン起動HTML は HEAD メソッドで <engine>/index.html を自動探索する ため、サーバーは HEAD（静的配信のみ）にも応答する

HTTP サーバーグループと共通仕様

  • Enable チェックで組み込み HTTP サーバーを起動/停止する （checkBox_server_toggle、QSettings に永続化・既定 ON）。
  • サーバはデフォルトでポート範囲 8089-8099 を試行してバインドする。ポートは スピンボックスまたは :80/:443 プリセットボタンで指定できる。
  • サーバは 0.0.0.0 にバインドし、LAN 共有は本機能の仕様。ユーザーへ見せるURL （プレゼン共有ボタン・パネルのサーバーステータス・起動時メッセージ・bridge openPresent/serverStatus/startServer の network_url）は 外部PCが接続できるよう http://<LAN-IP>:<port> を優先表示し、 LAN IP が取れない場合のみ localhost へフォールバックする。 共有ボタンはURLをクリップボードへもコピーする。外部PCから届かない場合は Check（Check Access 診断・ファイアウォールルール追加ボタン）を使う。
  • POST は /live/ 配下のみ受け付け、OPTIONS には CORS+Private Network Access プリフライトとして応答する（hosted エンジン https→localhost の fetch 用）。
