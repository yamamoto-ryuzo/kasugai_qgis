2. Live タブ — Canvas Live View

geo_webview ドキュメント / 使い方

使い方

Live タブ（Web タブの直後に動的挿入）は、エクスポート不要の常駐 live ビューの起動と、ライブ連携中の Canvas 操縦を QGIS 側へ集約します。

Open Live View（起動）

  • エンジン選択コンボ＋Open Live View — 常駐 live ビューを既定ブラウザで開く。 ?kasc=<base>/live/kasc が現在プロジェクトから .kasc を毎回オンデマンド生成するため エクスポートは不要（編集内容は常に最新）。エンジン供給元は Web タブの CDN: コンボに従う
  • 起動経路は Live タブのボタン / ツールバー「Open Canvas Live View」/ bridge liveView の3系統

双方向連携（追従・選択）

  • Follow QGIS canvas — Canvas カメラを QGIS キャンバスへ追従
  • Show QGIS selection — QGIS 選択地物を Canvas でハイライト
  • Follow Canvas view — QGIS キャンバスを Canvas 視点へ追従（既定 ON）

Add to Canvas

  • レイヤ選択コンボ＋Add to Canvas — プロジェクトのベクターレイヤを live Canvas へオンデマンド追加

設定・ツール仕様

Live タブ（panel.py: _build_live_tab で動的生成、Web タブの直後に挿入）は Canvas Live グループを持ち、ライブ連携中の Canvas 操縦を QGIS 側へ集約します:

  • エンジン選択コンボ（Cesium/MapLibre/OpenLayers/Leaflet/GSI Maps/Navara）＋ Open Live View ボタン — 常駐 live ビューを既定ブラウザで開く
  • Follow QGIS canvas — Canvas カメラを QGIS キャンバスへ追従（live.controls.follow）
  • Show QGIS selection — QGIS 選択地物を Canvas でハイライト（live.controls.selection）
  • Follow Canvas view — QGIS キャンバスを Canvas 視点へ追従（live.controls.qgis_follow、既定 ON）
  • レイヤ選択コンボ＋Add to Canvas — プロジェクトのベクターレイヤを live Canvas へオンデマンド追加

起動経路は Live タブの Open Live View（エンジン選択コンボ付き）/ ツールバー「Open Canvas Live View」/ bridge liveView の3系統。 エクスポートは行わず、?kasc= が指す GET /live/kasc がリクエストごとに現在プロジェクトから .kasc をオンデマンド生成する（図6）。 エンジン供給元は Web タブの CDN コンボ（kasugai_hosted_channel、§1 図4）に従う （stable/unstable/custom URL=ホスト版、canvas=稼働中アプリ :8510、FILE=本サーバが指定 web/ を配信）。 生成 .kasc 内の live: 行で Canvas が双方向連携モードへ入り、 編集・視点・選択が相互反映される（図7・図8）。CDN ホスト版を含む Canvas の AI チャットは /live/mcp リレー経由で Live Driver のツールを使える（図9）。 POST は /live/ 配下のみ受け付け、従来の CORS 許可リストが適用される。

色分け（この節）: 橙 = live API（/live/*）

図6. Live View の起動とデータ供給 — 起動はブラウザで <engine>/?kasc=<base>/live/kasc を開くだけ。生成される .kasc の各行はエクスポート済みファイルではなく live API の URL を指し、データ・スタイル・描画はすべて :8089 がオンデマンドで供給する。

flowchart TB
    BTN["Open Live View<br/>（Live タブ・ツールバー<br/>bridge liveView）"]
    ENG["＜engine＞/?kasc=…/live/kasc<br/>（エンジン供給元は図4と同じ<br/>CDN コンボで解決）"]
    KASC["GET /live/kasc<br/>現在プロジェクトから毎回<br/>オンデマンド生成<br/>（エクスポート不要）"]
    BTN --> ENG --> KASC
    KASC -->|"geojson: 行"| F["GET /live/features<br/>GeoJSON<br/>layer=/bbox= 範囲読み"]
    KASC -->|"gpkg:/shp: 等<br/>ネイティブ参照行"| LF["GET /live/file/＜path＞<br/>原本ファイル配信"]
    KASC -->|"style= 参照"| ST["GET /live/style<br/>.qml オンデマンド出力"]
    KASC -->|"image: 行<br/>（変換不可レイヤ）"| RN["GET /live/render<br/>QGIS 描画 PNG"]

    class BTN,ENG,KASC,F,LF,ST,RN live;

/live/style が返す .qml 内のシンボル画像参照（svgmarker・rastermarker・svgfill 等）は、サーバ側で実ファイルへ解決したうえ /live/file/<encoded-abs-path> へ書き換えて出力される（エクスポート経路の canvas_data/ 複製に相当）。配信許可はレイヤソース原本に加え「QGIS SVG 検索パス・プロジェクト dir 配下」の実ファイルのみで、対象外パスは 403。

図7. QGIS → Canvas（編集・状態の配信） — 編集検出は LiveSyncController が 1.2s デバウンスで live.json の rev を更新し、Canvas はポーリングで変化を検出して /live/kasc を再取得。キャンバス状態・QGIS 選択は /live/state で公開される。live.controls（follow / selection / qgis_follow）の正は QSettings で、パネル Live タブ・POST /live/controls・bridge liveControls/liveSetControls が同じ状態を共有する。kasugai_live_sync 設定 ON のときは rev 更新ではなく差分再エクスポート＋liveSync 通知（従来モード）。

図8. Canvas → QGIS（視点・選択・作図の書き戻し） — Canvas での視点移動・選択・表示変更・作図は POST で QGIS へ書き戻す。POST /live/camera は controls.qgis_follow（「Follow Canvas view」、既定 ON）が有効なときのみ QGIS キャンバスへ適用される。

    end
    subgraph API[":8089 /live/*"]

        SEL["POST /live/selection<br/>選択"]
        WB["POST /live/writeback<br/>POST /live/features<br/>表示状態・作図"]
    end
    subgraph QGIS["QGIS 側"]
        PROJ["プロジェクトへ反映<br/>表示・フィルタ・テーマ・<br/>スクラッチレイヤ"]

    ENG2 --> CAM --> PROJ
    ENG2 --> SEL --> PROJ
    ENG2 --> WB --> PROJ
    classDef live fill:#fff3e0,stroke:#e65100,color:#bf360c;
    class CAM,SEL,WB live;

POST /live/camera は controls.qgis_follow（「Follow Canvas view」、既定 ON）が有効なときのみ QGIS キャンバスへ適用される。「Add to Canvas」（Live タブのレイヤコンボ＋ボタン / POST /live/controls の add / bridge liveAddToCanvas）は live.add_layers キュー（{seq,title}・上限50）へ積み、Canvas が /live/state ポーリングで新しい seq を検出して /live/features で現在表示範囲の地物を取得する。

図9. Live Driver MCP リレー（v4.12.0〜） — CDN ホスト版を含む Canvas の AI チャットが Live Driver のツール（qgis_pyeval・bridge_call・screenshot 等）を使う経路。ドライバの /mcp は Bearer 保護・CORS 無しでブラウザから直接 fetch できないため本リレーがある。任意コード実行が乗るため TCP ピアが loopback の接続のみ許可（他 /live/* より露出を絞る）。

flowchart LR
    AI["Canvas AI チャット<br/>（CDN ホスト版・アプリ）"]
    DISC["GET /live/mcp-discover<br/>Live Driver セッション検出<br/>→ リレーURL を返す<br/>（トークンは返さない）"]
    RELAY["POST /live/mcp<br/>loopback 接続のみ<br/>トークンはサーバ側で付与<br/>Mcp-Session-Id を双方向伝播"]
    DRV["geo_driver /mcp<br/>qgis_pyeval・bridge_call・<br/>screenshot 等"]
    AI -->|"接続先の検出"| DISC
    AI -->|"JSON-RPC"| RELAY --> DRV
    classDef live fill:#fff3e0,stroke:#e65100,color:#bf360c;
    class DISC,RELAY live;
