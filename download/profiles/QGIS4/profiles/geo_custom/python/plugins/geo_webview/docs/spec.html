  • 目的: geo_webview プラグインの機能を明確に仕様化し、実装・運用・テストの基準を定める。

概要 — geo_webview の全体像

geo_webview は QGIS と KASUGAI Canvas をつなぐ連携プラグインです。 KASUGAI Canvas は Cesium/MapLibre/OpenLayers/Leaflet/GSI Maps/Navara のマルチエンジン WebGIS で、 geo_webview は現在の QGIS プロジェクトを Canvas へ「見せる」ための2本柱を提供します:

  1. サーバレス Web 配信（エクスポート） — プロジェクトのレイヤツリーを .kasc+canvas_data/ パッケージとして出力し、静的ホストや Canvas アプリで再生する。出力物＋エンジンを静的ホストへ置くだけで配信できる（§1 Web タブ）。
  2. Canvas Live View（双方向連携） — GET /live/kasc が現在 プロジェクトから .kasc をオンデマンド生成し（エクスポート不要）、編集・視点・選択・ 表示状態を QGIS↔Canvas 間で双方向に連携する（§2 Live タブ）。

Canvas は QGIS の Web 配布プレーヤーに留まらず、3D Tiles 等の重いコンテンツを 高速表示するメインブラウザとしても機能します（QGIS=編集・生成 / Canvas=表示 の 2画面運用）。QGIS4 は埋め込み WebView で WebGL が使えないため、表示は外部ブラウザに一本化 されています（v4.31 で埋め込みドックは廃止済み）。

両柱の共通基盤として、プラグインは 組み込み HTTP サーバー （既定ポート 8089-8099、0.0.0.0 バインドの LAN 共有仕様）を持ち、 エクスポート物の配信（/export-data/）・live API（/live/*）・ 画面共有（/present//screenshot）・パーマリンク受領 （/qgis-map）・Canvas web/ フォールバック配信（/<engine>/）を すべてこの1サーバが担います（エンドポイント一覧は HTTP API リファレンス）。

HTTP API リファレンス

  • GET /kasugai — .kasc+canvas_data/ エクスポート＋Canvas 登録。engine=（cesium|maplibre|openlayers|leaflet|gsimaps|navara、既定 cesium）・install=1（未検出時に配布ZIP取得）を受け付ける。応答 JSON {ok,url,via,dir,layers,tiles,engine}（§1）。
  • GET /live/* — Live View 連携 API（/live/kasc /live/features /live/file/（レイヤソース原本＋QML シンボル画像）/live/style /live/render /live/live.json /live/state /live/controls /live/camera /live/selection /live/writeback /live/mcp-discover /live/mcp。§2）。
  • GET /export-data/<rel> — 直近エクスポート出力先配下のファイル配信（.kasc/canvas_data/・起動HTML・xyz_tiles/ 等）。
  • GET /<engine>/... — インストール済み KASUGAI Canvas の web/ を静的配信（エンドポイント不一致パスのフォールバック解決）。
  • GET /present /present/state /screenshot — 画面共有ページ・キャンバス状態 JSON・キャンバス PNG（§6 共有グループ）。
  • GET /layouts — プロジェクトの印刷レイアウト一覧 JSON {ok,layouts:[{name,pages,w_mm,h_mm}]}（KASUGAI Canvas 印刷ダイアログが参照）。
  • GET /layout-pdf — QgsLayoutExporter で印刷レイアウトを PDF 出力（layout=<name> 省略時は先頭のレイアウト、dpi= 72–600・既定300）。キューイングで GUI スレッド実行・_layout_lock で直列化。
  • GET /received — 受領パーマリンク履歴 HTML。
  • GET /qgis-map — パーマリンク URL のパス。HTML は返さず、受領記録・External Control のナビゲートトリガとして使う（§6・§7）。
  • HEAD /export-data/・/<engine>/ — ランチャー HTML のエンジン自動探索プローブ用（静的配信のみ応答）。
  • OPTIONS — CORS+Private Network Access プリフライト（hosted エンジン https→localhost の fetch 用、§1 サーバグループ）。

投影 (CRS) ポリシー

  • .kasc エクスポートのベクターは EPSG:4326 に正規化して出力する（ネイティブ参照の GPKG/Parquet/FGB はクライアント側で処理）。
  • crs を指定しないパーマリンクは EPSG:4326 として解釈される。
  • 座標変換は QgsCoordinateTransform を利用。プロジェクトによっては外部の proj 定義が必要となる場合がある。

セキュリティ・運用上の注意

  • デフォルトで外部アクセスを許す設計だが、公開環境ではファイアウォールやプロキシでアクセス制御を厳格に行うこと（Share グループの MAC 認証も利用可、§6）。
  • External Control を有効にしていると任意の外部URLで QGIS の表示が書き換わるため、信頼できるネットワーク内または追加の承認フローを用いることを強く推奨。
  • ログを適切に出力し、受信元IP・タイムスタンプ・実行アクションを残す運用を推奨。

テスト・QA 手順

自動テスト候補:

  • server_manager.py のユニットテスト: ポート選定・バインド挙動のモックテスト。
  • URL パーサ（内部形式）の単体テスト（複数フォーマットのケース）。

手動テスト手順（QGIS 実環境）:

  1. QGIS を起動しプラグインをインストール。
  2. Export で .kasc+canvas_data/ を出力し、パネルの Engine: でエンジンを選び ▶ WebView を押してブラウザでそのエンジンが開くことを確認（出力→ブラウザ起動まで一発で行い、/kasugai と同じフォールバックが働く。未出力時はエクスポートを促すメッセージが出る）。
  3. External Control を ON にして、別ホスト（または同一ホスト）から /qgis-map?x=...&y=...&scale=... にアクセスして QGIS がジャンプすることを確認。
  4. /screenshot でキャンバス PNG が返ることを確認。
  5. /present ページがブラウザで開くことを確認。

テスト注意:

  • CI 環境では qgis.core や PyQt6 が無いため、これらをモックするかローカルでの手動確認が必要。

実装ファイルと責務マッピング

  • plugin.py — メインプラグインロジック、パーマリンク/ナビゲート、パネルイベント配線。
  • panel.py — パネル UI 実装（Web配信グループ、Live タブ動的生成、Layers/Filter/XYZ 各タブ、共有グループ、外部制御トグル等）。
  • panel_base.ui — Qt Designer の UI 定義（tabWidget_main: Web/Layers/Filter/XYZ/Other + 下部 External Control）。
  • server_manager.py — 組み込み HTTP サーバーの起動/停止・ルーティング（/kasugai /export-data/ /live/* /present /present/state /screenshot /received /layouts /layout-pdf /<engine>/ 等）。
  • http_server.py — HTTP 応答の低水準送信ユーティリティ。
  • kasugai_export.py — KASUGAI Canvas 連携（.kasc+canvas_data/ 生成、XYZ 焼き付け、起動HTML生成、プロジェクト登録、コマンド送信、フォールバックURL構築）。
  • live_kasc.py live_sync.py live_mcp.py — Live View の .kasc オンデマンド生成・編集差分検出・MCP リレー。
  • kasc_import.py — .kasc → QGIS プロジェクト再構成（bridge kascInspect/kascImport）。
  • scale_zoom.py — スケール/ズーム換算。
  • settings_dialog.py — 設定ダイアログ（KASUGAI インストール先・ホスト版チャンネル・Basemap Groups・Vector Export Format）。
  • bridge.py — AI/外部制御用ブリッジ（kasugaiExport 等）。
